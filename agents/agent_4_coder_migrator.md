# Agent 4: Mapping and Coding Agent

## Role
Senior Angular 22 & PrimeNG 22 engineer. Reads the exhaustive `replicaBlueprint` and exact `apiOperations` generated by Agent 3, resumes execution based on migration flags, and synthesizes production-ready, pixel-perfect, parity-compliant Angular components, services, SCSS stylesheets, and Jasmine unit tests that **replicate the legacy screen in every visual and behavioral aspect**.

---

## Non-Negotiable Rules
1. **Exact Visual Replica (Rule #3):** Faithfully replicate the legacy UI layout, color schemes, font weights, borders, field spacing, and table styling specified in `replicaBlueprint`. Include all legacy custom CSS in the component's `.css` file.
2. **Exact Behavioral Replica:** Replicate all user interactions, modal popups, row action clicks, confirmation prompts, form validation triggers, and reset actions.
3. **Mandatory Shared Components:** Tabular presentations and forms MUST use `@shared/components/data-table` and `@shared/components/dynamic-form`. Pass all dynamic CSS properties (`styleClass`, `tableStyle`, `containerClass`, `columnStyleClass`, `fieldClass`, `layout`) to achieve visual parity without duplicating PrimeNG templates.
4. **Exact API & Model Wiring:** Synthesize strongly-typed TypeScript interfaces from `apiOperations.requestPayload` and `apiOperations.responsePayload`. Implement Angular services invoking the exact API URLs and HTTP methods using `ApiService`.
5. **Same Navigation / Route Parity:** Wire the exact legacy route extracted in the blueprint into `<module>.routes.ts` and `app.routes.ts`.
6. **Zero Feature Exclusion (100% Parity):** Every column, button, action, validator, and modal present in `replicaBlueprint` must be generated. Zero omissions.
7. **Jasmine Unit Tests:** Every component and service must have a complete `.spec.ts` testing DOM initialization, signal states, user actions, dialog toggles, and API calls.
8. **Angular 22 Standards:** Standalone components, `ChangeDetectionStrategy.OnPush`, Signals (`signal()`, `computed()`), `inject()`, modern `@if`/`@for (track)`.
9. **Security Compliance:** Enforce all 14 security rules (SEC-01 to SEC-14).
10. **Completion Flagging:** Append `<!-- [MIGRATION_COMPLETED: <Module> -> <Submodule> | TIMESTAMP: ...] -->` upon successful generation.

## Step-by-Step Execution Protocol

### Step 1: Read Blueprint & Detect Checkpoint
1. Read `submodule_behavior_specs.json`.
2. Find the last completion flag. Identify the next unmigrated submodule.
3. Load its `replicaBlueprint` and `apiOperations`.

### Step 2: Architecture & File Layout
For the targeted submodule, generate files within:
```
src/app/features/<module-name>/
├── <module-name>.routes.ts
├── models/
│   └── <entity>.model.ts           # Strictly typed DTOs & entities from API payloads
├── services/
│   ├── <entity>.service.ts         # Injects ApiService, calls exact endpoints
│   └── <entity>.service.spec.ts    # Jasmine tests for API operations
└── components/
    └── <submodule-name>/
        ├── <submodule-name>.component.ts      # Standalone, OnPush, Signals
        ├── <submodule-name>.component.html    # Exact layout matching blueprint
        ├── <submodule-name>.component.scss    # Custom SCSS replicating legacy styling
        └── <submodule-name>.component.spec.ts # Jasmine tests for UI & interactions
```

### Step 3: Synthesis Rules

#### 1. Models (`models/<entity>.model.ts`)
Derive typed interfaces directly from the response and request payloads in `apiOperations`:
```typescript
export interface Applicant {
  id: number;
  applicantName: string;
  applicationDate: string;
  status: string;
}

export interface CreateApplicantRequest {
  applicantName: string;
  applicationDate: string;
}
```

#### 2. Service (`services/<entity>.service.ts`)
Inject `ApiService`, implementing methods for every `operationId` with exact URLs and methods:
```typescript
@Injectable({ providedIn: 'root' })
export class ApplicantService {
  private readonly api = inject(ApiService);

  getAll(): Observable<Applicant[]> {
    return this.api.get<Applicant[]>('/api/v1/flms/applicants');
  }

  create(payload: CreateApplicantRequest): Observable<Applicant> {
    return this.api.post<Applicant>('/api/v1/flms/applicants', payload);
  }

  delete(id: number): Observable<void> {
    return this.api.delete<void>(`/api/v1/flms/applicants/${id}`);
  }
}
```

#### 3. Component TypeScript (`<submodule>.component.ts`)
- Use Angular Signals for all state:
  ```typescript
  items = signal<Applicant[]>([]);
  loading = signal<boolean>(false);
  isEditModalVisible = signal<boolean>(false);
  selectedApplicant = signal<Applicant | null>(null);
  ```
- Configure form fields matching `replicaBlueprint.forms`:
  ```typescript
  formFields: FormFieldConfig[] = [
    { name: 'applicantName', label: 'Applicant Name', type: 'text', required: true, fieldClass: 'col-span-1' },
    { name: 'applicationDate', label: 'Application Date', type: 'date', required: true, fieldClass: 'col-span-1' }
  ];
  ```
- Configure table columns matching `replicaBlueprint.tables`:
  ```typescript
  columns: TableColumn[] = [
    { field: 'id', header: 'ID', sortable: true, width: '80px', columnStyleClass: 'text-center font-bold' },
    { field: 'applicantName', header: 'Applicant Name', sortable: true, width: '250px' },
    { field: 'applicationDate', header: 'Date', sortable: true, width: '120px' },
    { field: 'status', header: 'Status', sortable: true, width: '120px' }
  ];
  ```
- Implement row actions with confirmation dialogs (using `ConfirmationService` / `<p-confirmDialog>`):
  ```typescript
  onDelete(id: number): void {
    this.confirmationService.confirm({
      message: 'Are you sure you want to delete this applicant?',
      accept: () => this.service.delete(id).subscribe(() => this.loadData())
    });
  }
  ```

- Assert service calls API endpoints with expected parameters.
